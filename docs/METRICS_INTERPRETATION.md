# How to read the current local metrics

The current local dev dashboard is meant to verify the full Infineon pipeline before
we spend GPU time on Leonardo.

## Current n-gram baseline numbers

Typical current run after:

```bash
make dev-split
make train-ngram
```

is around:

| Task | Metric | Typical value | Interpretation |
|---|---:|---:|---|
| Task 1 next step | Top-1 | ~0.687 | Strong for a suffix-memory baseline. It gets the exact next step right about two thirds of the time. |
| Task 1 next step | Top-5 | ~0.928 | Good demo number: the correct next step is usually in the short candidate list. |
| Task 1 next step | MRR | ~0.807 | The correct token is usually near the top, not just barely inside top-5. |
| Task 2 completion | Token accuracy | ~0.421 | Acceptable baseline; full-route completion is much harder than next-step prediction. |
| Task 2 completion | Exact match | ~0.005 | Expected to be low because full semiconductor routes are long; one wrong branch breaks exact match. |
| Task 3 anomaly | F1 invalid | 1.000 | Expected on the local dev set: anomalies are injected rule violations and the detector uses the official validator. |
| Task 3 anomaly | Rule attribution | ~0.690 | The validator always catches invalid routes, but the first/primary rule label does not always match the injected rule. |

## Is Task 3 F1=1.0 suspicious?

No, not in this local setup. Task 3 is deliberately separated from sequence learning:

- the local invalid examples are generated by injecting known rule violations;
- the detector calls the official `validate_sequence()` logic from the Infineon data generator;
- therefore invalid/valid classification can be perfect even though the model is not a neural anomaly detector.

Pitch this as a strength: the neural model learns route distribution for Task 1/2,
while the hard-rule layer enforces process invariants for Task 3.

## What should improve next?

The n-gram baseline is already good at Task 1. The small Transformer should be
used to improve generalization and reduce pure memorization. The main target for
improvement is Task 2 completion quality, not Task 3 classification.
